# 最終スコア表（llama.cpp との同一条件対戦）

すべて RTX 3070 8GB / 単一 GPU / 同一モデルの GGUF（Q4_K_M）と int4 で比較。
数値は tok/s。「比」は kaze ÷ llama.cpp。
**測定は同一 GPU 状態で数分差**、各セルは同じハーネス（`bench/compare_kaze_server.py` /
`bench/compare_llama_server.py` / `bench/compare.py` / llama-bench）で取得。

## 1. 単一ストリーム（batch 1）

| model | kaze int4 decode | llama.cpp tg128 | 比 | kaze prefill | llama.cpp pp512 | 比 |
|---|---|---|---|---|---|---|
| 0.5B | **870.9** | 492.7 | **+77%** | **48,429** | 22,881 | **+112%** |
| 1.5B | **334.9** | 263.1 | **+27%** | **18,557** | 12,735 | **+46%** |
| 3B | **210.0** | 168.5 | **+25%** | **9,145** | 7,020 | **+30%** |
| 7B | **87.9** | 87.7 | **±0%（互角）** | **4,426** | 3,383 | **+31%** |

（2026-11-16 の涼しい時間帯に取り直し。decode は双方 128 トークン生成・ignore_eos、
prefill は 512。**7B の decode は以前 +14% と書いていたが、それは相手が throttled だった
ときの比較で、同条件では互角**でした）

## 5. 投機的デコード（prompt-lookup、単一ストリーム、既定 ON）

エンジン直（反復プロンプト、`bench/check_spec_long.py`）:

| 文脈 | plain | 投機 | 倍率 |
|---|---|---|---|
| 512 | 794 | **8,628** | **10.9x** |
| 1,024 | 801 | **8,303** | **10.4x** |
| 4,096 | 693 | **3,056** | **4.4x** |

**HTTP サーバ経由**（128 トークン生成、`bench/server_spec.py`）:

| モデル | 生成長 | 投機 OFF | 投機 ON | 倍率 |
|---|---|---|---|---|
| 0.5B・コード | 512 | 837 | **4,907** | **5.86x** |
| 0.5B・コード | 1,024 | — | **5,401** | — |
| 0.5B・散文 | 128 | 853 | **1,898** | **2.22x** |
| 0.5B・散文 | 512 | 837 | **4,978** | **5.95x** |
| 0.5B・4K 文脈・コード | 128 | 644 | **2,691** | **4.18x** |
| 3B・4K 文脈・コード | 128 | 176.8 | **1,119.5** | **6.33x** |
| 7B・4K 文脈・コード | 128 | 74.3 | **792.5** | **10.66x** |
| 3B・コード | 128 | — | **1,528** | — |
| 3B・コード | 512 | 172 | **2,584** | **15.0x** |
| 7B・コード | 128 | 84.7 | **888** | **10.5x** |
| 7B・コード | 512 | — | **1,472** | — |

（`--spec-k` の既定を 16 に修正した後の値。修正前は CLI が 8 を使っていて、
7B の 512 生成で 445 → **1,472 tok/s** と 3.3 倍の差がありました）

**モデルが大きいほど、生成が長いほど倍率が上がります**（1 step のコストが高いほど、
1 step で複数トークン出す価値が大きい）。7B・512 生成では **llama.cpp（77 tok/s）の 19 倍**。

効かない入力では自動で通常 decode に戻ります（0.99〜1.01x）。同時 2 本以上では無効化
（2 本で 0.92x だったため `spec_max_batch=1`）。

## 6. 再現コマンド

```bash
# 単一ストリーム
python3 bench/compare.py '{"engine":"kaze","model":"/models/Qwen2.5-0.5B-Instruct","kind":"int4","lm_head_kind":"int4","speculative":false}'
bench/llamacpp/llama.cpp/build/bin/llama-bench -m bench/llamacpp/models/Qwen2.5-0.5B-Instruct-Q4_K_M.gguf -p 512 -n 128 -r 3 -ngl 99

# サーバ同士（<n> <prompt_tokens> <gen_tokens>）
python3 -m kaze serve --model ... --kind int4 --lm-head-kind int4 --port 8099
python3 bench/compare_kaze_server.py 8099 32 32 64
python3 bench/compare_llama_server.py bench/llamacpp/models/<model>-Q4_K_M.gguf 32 32 64

# 一括検証（テスト + 一致 + 品質 + ベンチ）
./bench/check_all.sh
```

## 7. 注記

- 同時実行の数値は prefill を含む（両エンジンとも同じ条件）
- 7B の 64 本同時と 4K×8 は llama.cpp が起動できないため比較不能（kaze の実測値のみ）
- 数%の差は GPU のドリフトに埋もれるため、**同一プロセス内の交互 A/B** でのみ判断しています
